## Architecture

Direct Lambda IAM invocations without any HTTP envelope may create/list/archive/restore campaigns. Share link: `https://app.proairesis.digital/api/campaigns/r/roleclue-v1-linkedin-202610`. Its only destination is the fixed app root, with bounded `rc_campaign` and UTM tags; it cannot redirect elsewhere. `rc_test=1` and known bots remain excluded and visibly reported. Plain/direct app traffic has a separate direct bucket. Link requests are anonymous aggregate counters, not identified users.

## Public API / browser contract
- `GET /api/campaigns/r/{slug}`: 302 to fixed app root with campaign tags; unknown slug 404; archive keeps links resolvable. Record raw/excluded requests without raw IP/query/UA storage.
- `POST /api/analytics/session`: `{consent:true,campaign,visitor,session,test}` where visitor/session are random UUIDv4 created only after consent; campaign is a registered slug or `direct`. Return `{token,expiresAt}` signed with a domain-separated HMAC derived from existing guest secret. Sessions have a fixed 30-minute expiry; inactivity is measured separately from the last browser event; visitor expiry 30 days. Enforce bounded input and keyed-IP issuance limits; no raw IP is retained.
- `POST /api/analytics/events`: `{token,events:[{id,kind,step?}]}`; at most 10 allowlisted events, body <=4096 bytes; signed scope/test/expiry; retry-safe dedupe. No arbitrary text/properties or client timestamp retention. Client cannot send payment/letter-success/server-verification events.
- Authenticated app calls may carry `X-RoleClue-Analytics: <token>`. Save consented context only in an account-owned record, excluded from account export and naturally removed by account deletion. No reporting of identity values. Bind checkout/generation starts to their originating consented session so async completion cannot be attributed to another tab/session.
- Test data is excluded even if events are valid. Consent withdrawal clears browser identifiers and calls a scoped revocation endpoint so stored session context cannot keep collecting server events. Do not start or backfill pre-consent events. Analytics failures never fail the actual product action.

## Events and outcomes
UI event kinds: `app_visit`, `onboarding_started`, `onboarding_step` (1..4), `onboarding_completed`, `resume_started`, `resume_completed`, `profile_confirmed`, `matches_shown`, `matches_empty`, `role_opened`, `role_selected`, `signup_started`, `checkout_started`, `generation_requested`, `flow_error`. Restrict `flow_error` to stage/code enums; never accept exception strings. Prefer successful API observations for authoritative actions and retain UI observations only where genuinely visible.
Signup counts explicitly mean signup initiated then identity verified; they do not prove a first-ever Cognito account. Server-only kinds: `signup_verified`, `payment_confirmed`, `letter_succeeded`, `letter_failed`. Verify identity from authenticated requests. Payment success comes only after canonical Stripe verification and a newly completed payment tied to that originating checkout; seeing an already-active subscription is not a new conversion. Letter success comes only from a persisted successful generation, including asynchronous completion. Retry/webhook/reconciliation cannot double count; no synthetic production payments or paid AI calls are required for QA.

## Report contract
Existing response fields remain: `{campaigns:[{slug,name,destination,status,visits,visitors,requests,excluded}],daily:[{campaign,day,visits}],from,to,updatedAt}`. Add optional `sharePath:'/api/campaigns/r/'`, `destinations:[{value:'/',label:'RoleClue member app'}]` and per-campaign `funnel` with stage counts and diagnostic counts. Admin dates use Australia/Sydney, default last28 days, max90 days. Fetch bounded campaign/date partitions and fail honestly if report bounds are exceeded; no table scans/unbounded logs.

Headline funnel: visit, onboarding started/completed (individual 1..4 steps also shown), profile confirmed, matches shown, role selected, signup verified, checkout started, payment confirmed, letter succeeded. Resume use and empty/error outcomes are diagnostics because upload may be skipped. Count reached sessions without claiming ordered conversions when returning users skip steps. Prior-stage conversion numerator is intersection with the prior-stage cohort; show denominator. Unique browsers are random-browser estimates. Drop-off means inactive >=30 minutes with that last completed stage and no later stage; recent/active sessions are separate and never called quit. Returning/skipped paths and in-progress sessions cannot imply product failure. Show per-campaign daily sessions, errors, inactivity and measurement coverage. No consented measurement means unavailable journey data, not zero total people. Raw redirect requests cannot be used as exact consent coverage or unique humans.

## Privacy / retention / security

No CV, profile answers, work rights, role/letter text, email, query strings or raw IP in analytics. Strict event schemas and bounded IDs; public rate limits; dedupe; origin gate intact. Account deletion removes context pointers; analytics records are pseudonymous sessions, not retained account/sub values.
